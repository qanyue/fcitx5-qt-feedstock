Personal GitHub Actions builds
=============================

This fork builds `fcitx5-qt6` for personal use and saves `.conda` packages as
GitHub Actions artifacts. It does not publish packages to conda-forge or Anaconda.org,
and does not require `BINSTAR_TOKEN`, `FEEDSTOCK_TOKEN`, or `STAGING_BINSTAR_TOKEN`.

1. Push a commit, open a pull request, or run **Build conda package** manually from the Actions tab.
2. Open the workflow run and download the `conda_pkgs` artifact for your Linux architecture
   (`linux_64_` or `linux_aarch64_`). For example:
   `fcitx5-qt-feedstock_conda_pkgs_<run-id>_linux_aarch64_.tar.zst`.
3. Extract the `.tar.zst` archive to obtain the `.conda` package under its platform directory.
   Artifacts are retained for 30 days.

The default Qt version is 6.11.3, matching the `qt6-main 6.11.3.*` dependency of
conda-forge's latest PySide6 6.11.3 when checked on 2026-11-02. The plugin's runtime
dependency is restricted to the same Qt patch version because it uses private Qt APIs.
The ppc64le build is skipped because conda-forge does not provide this Qt version there.

The generated artifact script archives package directories and channel metadata,
excluding dependency caches and build environments. Failed builds can also upload
separate work directory and environment archives for debugging.

The workflow and `.scripts/` are generated by `conda-smithy rerender` from
`conda-forge.yml`: `conda_forge_output_validation: false` disables conda-forge
output authorization checks, `github_actions.upload_packages: false` disables
package publishing, and `workflow_settings.store_build_artifacts: true` enables
CI artifacts. Change these settings and rerender rather than editing generated scripts.
`skip_render` preserves this README when rerendering.
The upstream conda-forge installation and release information below does not describe
this fork's artifacts.

Installing fcitx5-qt6
=====================

Installing `fcitx5-qt6` from the `conda-forge` channel can be achieved by adding `conda-forge` to your channels with:

```
conda config --add channels conda-forge
conda config --set channel_priority strict
```

About conda-forge
=================

[![Powered by
NumFOCUS](https://img.shields.io/badge/powered%20by-NumFOCUS-orange.svg?style=flat&colorA=E1523D&colorB=007D8A)](https://numfocus.org)

conda-forge is a community-led conda channel of installable packages.
In order to provide high-quality builds, the process has been automated into the
conda-forge GitHub organization. The conda-forge organization contains one repository
for each of the installable packages. Such a repository is known as a *feedstock*.

A feedstock is made up of a conda recipe (the instructions on what and how to build
the package) and the necessary configurations for automatic building using freely
available continuous integration services. Thanks to the awesome service provided by
[Azure](https://azure.microsoft.com/en-us/services/devops/) and [GitHub](https://github.com/)
it is possible to build and upload installable packages to the
[conda-forge](https://anaconda.org/conda-forge) [anaconda.org](https://anaconda.org/)
channel for Linux, Windows and OSX respectively.

To manage the continuous integration and simplify feedstock maintenance,
[conda-smithy](https://github.com/conda-forge/conda-smithy) has been developed.
Using the ``conda-forge.yml`` within this repository, it is possible to re-render all of
this feedstock's supporting files (e.g. the CI configuration files) with ``conda smithy rerender``.

For more information, please check the [conda-forge documentation](https://conda-forge.org/docs/).

Terminology
===========

**feedstock** - the conda recipe (raw material), supporting scripts and CI configuration.

**conda-smithy** - the tool which helps orchestrate the feedstock.
                   Its primary use is in the construction of the CI ``.yml`` files
                   and simplify the management of *many* feedstocks.

**conda-forge** - the place where the feedstock and smithy live and work to
                  produce the finished article (built conda distributions)


Updating fcitx5-qt6-feedstock
=============================

If you would like to improve the fcitx5-qt6 recipe or build a new
package version, please fork this repository and submit a PR. Upon submission,
your changes will be run on the appropriate platforms to give the reviewer an
opportunity to confirm that the changes result in a successful build. Once
merged, the recipe will be re-built and uploaded automatically to the
`conda-forge` channel, whereupon the built conda packages will be available for
everybody to install and use from the `conda-forge` channel.
Note that all branches in the conda-forge/fcitx5-qt6-feedstock are
immediately built and any created packages are uploaded, so PRs should be based
on branches in forks, and branches in the main repository should only be used to
build distinct package versions.

In order to produce a uniquely identifiable distribution:
 * If the version of a package **is not** being increased, please add or increase
   the [``build/number``](https://docs.conda.io/projects/conda-build/en/latest/resources/define-metadata.html#build-number-and-string).
 * If the version of a package **is** being increased, please remember to return
   the [``build/number``](https://docs.conda.io/projects/conda-build/en/latest/resources/define-metadata.html#build-number-and-string)
   back to 0.
